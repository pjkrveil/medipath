# MediPath — 약 배분 플래너

대한민국 주말·공휴일·개인 휴일에는 집, 나머지 업무일에는 회사에서 먹는 약의 수량과 이동 일정을 계산하는 정적 웹앱입니다. 첨부 WeatherOps 프로젝트의 상단 메뉴, 요약 카드, 타임라인 구성을 참고해 청록색(집)과 남색(회사)으로 정리했습니다. 원본 프로젝트의 환경 파일·서버 코드·로그·인증정보는 포함하지 않았습니다.

## 바로 실행

`dist/index.html`을 최신 Chrome, Edge, Safari, Firefox에서 여세요. 별도 서버, npm 설치, API 키가 필요하지 않습니다. 함께 제공된 `MediPath.html`도 같은 앱을 한 파일로 실행합니다. HTML의 스크립트를 차단하는 문서 미리보기에서는 다운로드 후 브라우저로 열어 주세요.

일반 웹 주소로 로컬 실행하려면 Python 3 설치 후:

```sh
python3 -m http.server 8080 --directory dist
```

브라우저에서 `http://localhost:8080`을 엽니다. 파일로 연 경우 브라우저마다 저장 동작이 다를 수 있으므로 장기 사용은 배포된 웹 주소를 권장합니다.

## 사용 순서

1. 병원 방문일과 처방 기간(1~365일)을 입력합니다.
2. 방문 전에 이미 먹었다면 **먹고 방문**, 처방받은 약으로 그날 먹는다면 **다녀와서**를 선택합니다.
3. **계획 계산**을 누릅니다. 초기 수량은 처방일수 × 하루 복용량으로 채웁니다.
4. 각 약의 실제 **받은 수량**을 확인합니다. 직접 바꾼 수량은 기간을 수정해도 유지됩니다. **처방일수에 맞춤**을 누르면 다시 일수 기준으로 계산합니다.
5. **팩·통 유지** 또는 **알·봉 단위로 나누기**를 선택합니다. 집 또는 회사 수량을 바꾸면 반대편은 총량에서 자동 계산합니다. **자동**은 추천 배분으로 돌아갑니다.
6. **나의 휴일**에서 연차·회사 휴무·재택일을 단일 날짜 또는 기간으로 추가합니다.
7. 달력 날짜를 누르면 당일 복용·이동 이후 잔량이 표시됩니다. **챙겨야 할 날**에서 이동 수량과 시점을 확인합니다.

### 기본 약 설정

| 약 | 1일 복용량 | 포장 | 포장 유지 시 이동 단위 |
|---|---:|---|---|
| A | 1알 | 10알 알루미늄 팩 × 3팩 | 10알 팩, 개봉 후 남은 팩 |
| B | 1봉(팩) | 90봉 들어 있는 통 × 1 | 90봉 통, 개봉 후 남은 통 |
| C | 2알 | 30알 통 × 1 | 30알 통, 개봉 후 남은 통 |

각 카드의 **설정**에서 이름·하루 복용량·수량 단위·팩/통당 수량·상자당 팩/통 수를 변경할 수 있습니다. 설정은 실제 처방을 입력하기 위한 것이며 앱이 복용량을 추천하지 않습니다. 원포장을 나눠 보관할 수 있는지는 실제 약의 보관 지침에 따라 선택하세요.

## 계산 방법

- 방문 전에 먹었다면 새 처방 시작일 = 방문일 + 1일. 다녀와서 먹는다면 시작일 = 방문일.
- 마지막 날 = 시작일 + 처방일수 − 1일. 날짜는 한국 달력 기준 문자열로 취급하고 날짜 산술은 UTC 자정으로 처리해 시간대·서머타임에 의한 하루 오차를 피합니다.
- 집 필요량 = 집 복용일수 × 하루 복용량. 회사도 같은 방법으로 계산합니다.
- 나눠 담기는 집 필요량만큼 배분하고 나머지는 회사에 둡니다.
- 포장 유지는 집 필요량을 팩/통 단위로 올림해 배분하되 실제 받은 수량을 넘지 않습니다. 직접 지정할 때도 집 또는 회사 중 한쪽은 포장 단위의 배수가 되어야 합니다. 받은 수량이 완전한 포장으로 나눠떨어지지 않으면 부분 포장 하나를 인정합니다.
- 회사 복용일에 회사 재고가 모자라면 출근 시 집에서 가져옵니다. 연속 휴일 직전 업무일에는 휴일 전체의 집 복용량을 확보하도록 퇴근 시 회사에서 가져옵니다.
- 기간이 휴일로 시작하고 집 재고가 부족하면 **시작 전 준비**를 별도로 표시합니다. 휴일에 회사에 방문할 수 있다고 가정하지 않습니다. 이 물량은 시작 전에 확보해야 합니다.
- 포장 유지에서는 남은 내용물을 포함한 팩/통 자체가 이동합니다. 하나뿐인 90봉 통은 업무일·휴일 경계마다 왕복할 수 있습니다. 여러 약의 같은 날짜·시점 이동은 한 그룹으로 표시합니다.
- 이동 단위는 잔량이 작은 포장부터 선택합니다. 전역 최소 이동 횟수를 구하는 최적화 알고리즘은 아닙니다.
- 처방 전 잔약은 별도로 관리하지 않습니다. 필요하면 받은 수량에 합산합니다. 처음 배분된 수량이 양쪽 장소에 준비되어 있다는 가정입니다.
- 1일 복용량이 부족한 날은 부분 복용으로 차감하지 않고 부족으로 표시합니다. 총량 부족과 최초 부족일을 확인할 수 있습니다.

### 재현 가능한 예시

2026.09.23 방문, 다녀와서 복용, 90일, 추가 휴일 없음:

| 항목 | 값 |
|---|---|
| 복용 기간 | 2026.09.23 ~ 2026.12.21 |
| 집 / 회사 복용일 | 30일 / 60일 |
| A 처음 배분 | 집 30알 / 회사 60알 |
| B 처음 배분, 통 유지 | 집 90봉 / 회사 0봉, 이후 통 이동 일정 27회 |
| B 처음 배분, 봉 단위 나누기 | 집 30봉 / 회사 60봉, 추가 이동 없음 |
| C 처음 배분 | 집 60알 / 회사 120알 |

B를 통째로 유지하는 경우 첫날 회사로 90봉을 가져가고, 첫날 복용 후 추석 연휴 전에 남은 89봉 통을 집으로 가져갑니다.

## 공휴일 범위와 갱신

**2026~2027년**의 명시적인 공휴일 데이터를 내장합니다. 확인일은 **2026.09.23**입니다. 2026년 노동절·제헌절 관련 개정, 선거일과 대체공휴일을 포함합니다. 2026년 추석 마지막 날은 토요일이지만 그 사유만으로 월요일을 대체공휴일로 만들지 않습니다. 현충일·신정에도 일률적인 대체공휴일을 만들지 않습니다.

확인일 이후 추가되는 임시공휴일은 **나의 휴일**에 넣으세요. 자동 인터넷 갱신은 하지 않습니다. 확인되지 않은 연도는 평일로 추측하지 않고 계산을 중단합니다.

다음 연도를 지원하려면 `dist/holidays.js`의 `data`에 공식 일자 목록을 추가하고 `min`, `max`, `reviewed`, 화면 안내·입력 날짜 범위를 갱신합니다. `dist/app.js`의 기본 날짜 범위도 함께 조정하세요. `tests/core.test.js`에 공식 연간 휴일 총수와 주요 날짜 회귀 검증을 추가한 후 배포합니다. 사용자 휴일 추가는 공휴일 데이터 지원 범위를 확장하는 기능이 아닙니다.

## 저장과 개인정보

- 초기에는 예시 계획이며 서버로 처방 내용을 보내지 않습니다. 외부 스크립트, 외부 폰트, 분석 서비스, API 요청이 없습니다.
- **이 기기에 계획 저장**을 켜면 이 브라우저의 localStorage에 저장합니다. 끄면 저장된 계획을 삭제합니다.
- 기기·브라우저 간 동기화나 계정 기능은 없습니다. 저장 실패 시 화면에 알립니다.
- **CSV 저장**은 초기 배분과 이동 일정, 부족량을 파일로 내려받습니다. 한국어 엑셀 호환 BOM 및 CSV 수식 입력 방어를 포함합니다.
- GitHub Pages에는 앱 코드만 올라갑니다. 사용자가 브라우저에서 입력한 처방은 GitHub 저장소에 기록되지 않습니다.

## GitHub Pages 배포

이 전달본은 GitHub 저장소에 업로드하거나 배포된 상태가 아닙니다. 저장소 및 계정 연결 정보가 제공되지 않아, 배포할 수 있는 소스와 자동화 설정을 제공합니다.

1. GitHub에서 새 저장소를 만들고 이 폴더의 **내용**을 `main` 브랜치에 올립니다. `dist`, `tests`, `package.json`, `.github/workflows/pages.yml`이 저장소 최상위에 있어야 합니다. 숨김 폴더 `.github`가 빠지지 않게 주의하세요.
2. 저장소 **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
3. **Actions → Test and deploy MediPath → Run workflow**를 실행합니다. 이후 `main`에 수정 사항을 올리면 다시 배포합니다.
4. 실행 결과의 `github-pages` 주소로 접속합니다. 정적 자산 경로가 상대 경로이므로 `사용자.github.io/저장소명/` 경로에서도 동작합니다.

자동화는 JavaScript 문법과 계산 테스트 통과 후 `dist`만 공개합니다. API 키나 별도의 시크릿은 필요하지 않습니다. 계정의 Pages 이용 조건과 저장소 정책에 따라 Pages 활성화가 필요합니다.

[GitHub 공식 배포 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## 개발과 검증

의존성이 없는 HTML/CSS/JavaScript입니다. Node.js 22 이상에서:

```sh
npm run check
npm test
```

검증에는 방문일 경계, 공휴일, 겹친 사용자 휴일, 포장 보존, 연휴 전 이동, 단일 통 왕복, 수량 부족, 수동 배분, 잔량 보존이 포함됩니다. 12개 테스트 안에 96개 날짜·기간·배분 조합의 재고 보존 검증을 포함합니다. 이 제작 환경에서는 실제 브라우저 화면 및 모바일 터치 검증을 수행하지 못했습니다. 배포 전 실제 브라우저에서 입력·팝업·다운로드와 모바일 화면을 확인해 주세요.

| 파일 | 역할 |
